# Data card

## 1. Synthetic demo corpus — `data/sample_docs/` (committed)

All 13 documents were **written by the team (AI-assisted)** for a **fictional** company, *Orbitly Inc.*,
and its SaaS product *Orbitly Workspace*. Every file says "SYNTHETIC" at the top. They contain no real
company's information. We use a synthetic corpus so the facts, versions and conflicts are fully known,
which makes the relevance labels exact.

| File | Format | Topic (brief category) | Version / date |
|---|---|---|---|
| account_access.html | HTML | Account access | — |
| api_usage_limits_v2.md | Markdown | Usage limits | v2.0, 2026-07-01 |
| billing_policy_2026.md | Markdown | Billing policy | 2026-01-01 |
| support_faq_v1.txt | TXT | FAQ: limits, billing | v1.x, 2025-03-15 |
| release_notes_v3.md | Markdown | Release notes | v3.0, 2026-10-01 |
| user_roles_permissions.md | Markdown | Account access / configuration | 2026-05-20 |
| onboarding_quickstart.md | Markdown | Configuration, seat limits | 2026-06-10 |
| security_faq_v2.txt | TXT | Security FAQ | v2.x, 2025-11-04 |
| troubleshooting_guide.html | HTML | Troubleshooting, error codes | 2026-09-12 |
| integrations_configuration.html | HTML | Product configuration | v3.0 |
| sso_admin_guide_v3.pdf | PDF (2 pages) | SSO configuration manual | v3.0, 2026-10-01 |
| data_retention_policy.pdf | PDF (2 pages) | Policy | 2026.1, 2026-01-01 |
| support_sla_policy.pdf | PDF (2 pages) | Support policy | 2026-04-01 |

PDFs are generated by `python -m scripts.build_sample_pdfs` (needs `pip install fpdf2`). Edit the text there
and regenerate, never by hand.

### Deliberate conflicts (for FR-06)

| ID | Topic | Disagreeing sources |
|---|---|---|
| C1 | API rate limit (Standard) | v1.x FAQ 100/min · v2.0 limits 300/min · v3.0 release notes 500/min |
| C2 | Refund window | 2026 billing policy 30 days · v1.x FAQ 14 days |
| C3 | Session timeout | v2.x security FAQ 8 h · v3.0 SSO guide + release notes 12 h |
| C4 | Max upload size | troubleshooting guide (Sep 2026) 100 MB · v3.0 release notes 250 MB |

C4 is intentionally tricky. The troubleshooting guide is **newer by date** but describes the **older version**.
"Latest date wins" would give the wrong answer, so the conflict has to be shown to the user.

### Other built-in traps

- Exact error codes (ERR-403, ERR-429) for testing BM25.
- Paraphrases that avoid the document's wording ("create accounts for new hires" means SCIM).
- Negative facts (Jira Server not supported, no Linux desktop app).
- "Money back when down" (SLA credits) vs "refund" (billing).
- HTML `<script>`, `<nav>` and `<footer>` that the loader must strip.

## 2. Labelled evaluation set — `data/eval/questions.jsonl` (committed)

There are 27 questions: 12 direct, 5 paraphrase, 4 conflict, 3 ambiguous, 3 unanswerable. The team wrote them
by hand from the corpus above.

- **Relevance labels** use doc + section level (`RelevanceLabel`). `doc_id` is the file name, lower-cased,
  with `_` replaced by `-` (for example `support_faq_v1.txt` becomes `support-faq-v1`).
- **Section** is the heading path joined with `" > "` and is matched as a prefix. PDF labels use
  `section: null`, meaning any section of the document, because PDF heading detection is heuristic.
- **Grade:** 3 = essential (contains the answer), 2 = supporting or conflicting source.
- **expected_status** checks fallback behaviour. Ambiguous questions should get `needs_clarification` and
  unanswerable ones should get `not_found`.

**Assumptions and limitations:** the questions were written by people who know the corpus, which may make
retrieval look easier than it would be for real employees. Labels were made by one annotator and not
cross-checked. The corpus is small (13 docs), so absolute metric values will not carry over to a large
real-world knowledge base.

## 3. Real public documents — `data/raw/` (git-ignored, never committed)

We may download a few publicly available HCLTech / HCL Software documents to show that ingestion works on real
enterprise files. They are copyrighted, so they **stay out of Git**. Each team member downloads them locally.
Sources and download dates are listed in `data/raw/SOURCES.md` (also git-ignored). They are not part of the
labelled evaluation.

## 4. Never commit

`.env`, real customer or employee data, confidential documents, `data/raw/*`, `data/uploads/*`, `models/*`.
